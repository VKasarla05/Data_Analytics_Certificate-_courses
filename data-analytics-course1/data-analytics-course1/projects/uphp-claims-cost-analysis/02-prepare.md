# Phase 2: Prepare

## Data source & format classification
Applying the Course 3 data-format framework to the dataset for this project:

| Classification | This dataset |
|---|---|
| First / Second / Third-party | **Third-party** — sourced from Kaggle, not collected by me or for this specific purpose |
| Primary / Secondary | **Secondary** — gathered/generated by someone else (synthetic claims data) |
| Internal / External | **External** — not stored inside a health plan's own systems |
| Structured / Unstructured | **Structured** — rows and columns (claims, member demographics, cost fields) |
| Qualitative / Quantitative | Primarily **quantitative** (costs, codes, dates), with some **nominal** categorical fields (plan type, diagnosis category) |

## Context (Who/What/Where/When/Why/How)
- **Who:** Kaggle contributor (leandrenash) — not an official health plan or government source
- **What:** Health insurance claims — member demographics, diagnosis/procedure info, claim cost, dates
- **Where:** Downloaded from Kaggle (kaggle.com/datasets/leandrenash/enhanced-health-insurance-claims-dataset)
- **When:** Published July 2024; represents synthetic/generated records, not a specific real time period
- **Why:** Built for ML/analytics practice — not originally collected for a specific health plan's stakeholder question
- **How:** Synthetically generated (not collected from real patients or real claims systems)

**Bias/credibility note:** because this is a synthetic dataset, it won't reflect the real
distribution of costs, diagnoses, or utilization patterns a real Medicaid population (like
UPHP's) would have. I'm treating this as a *practice dataset* to demonstrate the workflow —
any findings are illustrative, not representative of a real health plan's population, and
I'll say so explicitly in the final report (Share phase).
